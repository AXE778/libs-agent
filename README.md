# LIBS AI Agent

用大模型驱动一套工具链，去读和分析 **LIBS（激光诱导击穿光谱）** 数据。

你问「这批不锈钢数据采集质量怎么样」，它不是凭训练知识编一段话回答，
而是**真的去调 Python 读你的 CSV**，把算出来的数字解释给你听。

> 一句话架构：**大模型负责决策和解释，Python 负责计算。两者严格分离。**

---

## 为什么做这个

LIBS 数据分析的现状是：上位机软件负责采集和出图，分析靠人手工导数据、写脚本。
每换一批样品、换一个采集参数，脚本就得改一遍。

这个项目想验证一件事：**能不能让大模型自己判断「该算什么」，把计算交给可靠的代码。**
拆开就是三个必须解决的问题：

| 问题 | 做法 |
|---|---|
| 模型会编造数字 | 所有数字只能来自工具返回值，模型的职责是解释，不是计算 |
| 模型不会算 | 阈值判定、统计检验全写在 `tools/` 的 Python 里，改阈值就改结论 |
| 模型会误用工具 | 工具说明书（JSON Schema）里直接写清「不许做什么」，配纪律约束 |

代码按这两条线分成两层，**第 1 层永远不知道第 2 层怎么算的**：

```
用户提问
   │
   ▼
agent/          理解 + 决策 + 调工具          ← 只这一层碰大模型
   │  tool_calls（JSON）
   ▼
tools/          真正的计算（纯函数，不 print、不联网、不碰模型）
   │  结构化结果
   ▼
agent/          把结果翻译成人话
```

**关键收益**：以后把简单的阈值比较换成 PLSR、换成 NIST 谱线库、换成二维重建，
只需要改 `tools/`，Agent 一行都不用动。

## 快速开始

```bash
git clone <本仓库>
cd libs_agent

python -m venv .venv
.venv\Scripts\activate            # Windows；Linux/macOS 用 source .venv/bin/activate
pip install -r requirements.txt

# 先跑离线自检：不联网、不需要 API Key，看数据能不能读、9 个工具能不能跑
python scripts\selfcheck.py

# 想让它真去聊（需要一个 OpenAI 兼容的大模型 Key，见 .env.example）
copy .env.example .env            # 填上你的 Key
python main.py "有哪些数据"
```

> **⚠ 这两步不是一回事，别混。** 离线自检**完全不调用大模型**（所以不联网、不要 Key），
> 只把 9 个工具挨个跑一遍 —— 它回答的是「**数据能读、工具能跑吗**」，
> **回答不了**「模型会不会正确地挑工具、填参数」。
> 后者必须有 Key、必须能联网才能测。
> 项目里**没有本地模型**：所有对话都是把请求转发给云端（豆包 / Kimi / 商汤），**离线用不了**。

`.env.example` 里预置了**豆包（火山方舟）/ Kimi（Moonshot）/ 商汤（日日新）**三家，
换厂商只需要改 `.env` 里的一行 `LLM_PROVIDER`，代码零改动。

## 九个工具

Agent 看不见源码，它只能看见一份**说明书**（`agent/tool_registry.py` 里的 `TOOLS`）：
工具叫什么、干什么、要哪些参数。

| 工具 | 干什么 |
|---|---|
| `list_available_spectra` | 不传筛选 → 数据总览；传筛选 → 具体文件路径 |
| `describe_material_grid` | 把测点还原成二维网格，报出网格形状与缺测点 |
| `load_spectrum_summary` | 读一条谱：点数 / 波长范围 / 最强峰 / 信噪比 |
| `check_spectrum_quality` | 单条质量检查：打饱和 / 弱信号 / 背景偏高 / 孤立尖峰 / 波长轴 |
| `check_group_quality` | 整组批量检查 + 汇总（返回给模型的是摘要视图，不是上千行明细） |
| `plot_spectra` | 出图并存成 HTML |
| `analyze_element_lines` | 谱线与元素匹配（**输出是候选，不是「检出元素」**） |
| `generate_report` | 汇总成一份 Markdown 报告 |
| `preprocess_spectrum` | 预处理：插值 / 基线校正 / 平滑 / 归一化 |

调用链是这样的 —— 模型看不见你的代码，它只是在**申请**：

```
你      ：304 这组数据采集质量怎么样？
模型    ：我要调用 check_group_quality，参数 material=304
你的代码 ：（真的去读 25 个 CSV、算饱和、算信噪比）
模型    ：这组 25 条谱有 16 条在 652.38 nm 打饱和，峰顶被削平……
```

## 三个值得展开的设计决定

### 1. 模型不参与任何计算 —— 有可验证的证据

同一组数据、同一份代码，换一个厂家的模型跑，**生成的报告正文哈希完全相同**：
两个模型的报告正文 sha256 一致，只有抬头的时间戳不同。

这不是「结果差不多」，是**逐字节相同**。说明报告里的每个数字都来自 `tools/` 的纯计算，
换模型不会让结论漂移。

实测中模型确实会在没人拦着的时候自己算错 —— 比如把工具返回的「6 组 325 个文件」
汇总成「5 组 250 个」。所以现在凡是能聚合的，都在 Python 里算好了再给模型。

### 2. 判级全部由 Python 的阈值比较产生

「合格 / 不合格 / 需留意」这类判断，写在 `config/quality.py` 里，与模型完全无关。

同一条光谱，把量程上限从 65535 改成 70000，判级就从 `FAIL` 变成 `WARN` ——
**改阈值就改结论，模型只是把它翻译成人话。**

### 3. 平滑窗口必须自适应 —— 一个被实测逼出来的设计

一开始想当然地用了固定窗口（SG 滤波，0.8 nm）。实测三条真实光谱后发现：

| 光谱 | 最强峰 FWHM | 用固定 0.8 nm 窗口的后果 |
|---|---|---|
| 某不锈钢谱 | 0.163 nm ≈ **1.6 个像素** | 峰高损失 **55%**，数据被毁 |
| 另一条不锈钢谱 | 0.556 ~ 1.883 nm | 峰高损失 3.3%，几乎无损 |
| 另一台参数下的谱 | 0.174 ~ 0.632 nm | 峰高损失 0.3%，无损 |

**同一台仪器上峰宽差了 10 倍**，任何写死的窗口值都注定要坑掉其中一边。
所以现在默认自动选窗：候选窗口从小到大试，取「最高峰变化 |Δ| ≤ 2%」的最大那个，
并把整张候选扫描表一起返回 —— 选了哪个、为什么，可以被复核，不是黑箱。

顺带一个反直觉的实测结论：**平滑不总是把峰压低**。有一条谱平滑后最高峰反而略升，
因为峰顶原本的小凹口被填平了。所以判据用的是变化的**绝对值**。
（实测里模型真的把负号读反过一次，把「被抬高 2.3%」说成「被压低 2.3% 超阈值」——
现在会额外返回一句人话描述。）

## 数据说明（重要）

**本仓库不包含任何真实测量数据，也不包含谱线库。**

| 内容 | 状态 |
|---|---|
| `data/sample/` 里的 CSV | **程序合成的**，由 `tools/make_sample_data.py` 生成，**没有定量意义** |
| 谱线库 `data/reference/` | **未包含** —— 那是仪器/软件自带的数据库文件，不便再分发。请自备（见下） |

合成数据不是随便造的噪声，它的统计特征照着真实仪器还原：波长轴 180.6~954.0 nm、
7745 点、步长非均匀（0.065~0.142 nm）、峰位用真实原子跃迁波长、峰宽差异约 10 倍、
一部分故意打饱和并埋了孤立尖刺。**目的是让流程能被完整验证，不是冒充真实数据。**

重新生成：

```bash
python tools\make_sample_data.py
```

固定随机种子，每次生成完全一致。

### 想让它读你自己的数据

两种方式：

```bash
# 方式一：环境变量（推荐，不会在 git 里留下本地差异）
set LIBS_DATA_ROOT=D:\你的数据目录
python main.py "有哪些数据"

# 方式二：改 config/paths.py 里的默认值
```

目录结构约定：数据根目录下每个子目录是一个测量组，文件名形如
`DATA-<时间戳>-X<列号>-Y<行号>-<第几发>.csv`（二维扫描网格），
或者任意名字的 `wavelength,intensity` 两列 CSV。

### 想用元素匹配（Step 7）

需要自备一份谱线库放到 `data/reference/intensity.csv`，列至少包含
`Element, Wavelength, intensity, Aki`（Wavelength 单位 nm）。

获取途径：① 你的 LIBS 软件安装目录里通常带一份，导出成 CSV；
② [NIST Atomic Spectra Database](https://physics.nist.gov/asd) 公开可查。

缺这个文件时，只有元素匹配相关功能不可用（`selfcheck.py` 会把它标成「跳过」而不是「失败」），
读谱、质量检查、预处理、绘图全部正常。

## 这个项目**不**做的事

写在前面，避免误用：

- **不做浓度定量。** 数据没有浓度标定，只有特征强度。任何「含量是多少」的问题都应当被拒绝回答。
- **不把「候选谱线」说成「检出元素」。** 谱线库在仪器波段内每 nm 有上百条线，
  单个峰对上一条线几乎不构成证据。判定只有三档：有支持（≥2 个独立峰且置换检验 p<0.01，
  仍只是「值得人工复核」）/ 不可采信 / 证据不足。
- **不做外推。** 统一波长轴时取各条谱覆盖范围的**交集**，超出覆盖的波段一个点都不生成，
  不填 NaN、不编曲线。
- **不把预处理产物当原始数据用。** 质量检查（饱和、信噪比、尖峰）必须基于原始谱 ——
  平滑会把疑似尖峰磨平、把饱和的平顶拉圆，在预处理过的谱上做质量检查会得出**假的合格结论**。

```
libs_agent/
├── main.py                     # 命令行入口（问一句就退出 / 连续对话）
├── scripts/
│   └── selfcheck.py            # 离线自检：不联网、不花钱，验证工具链是否通
├── server/app.py               # FastAPI 后端：/health /tools /chat /sessions
├── agent/                      # 「理解与决策」层 —— 只这一层碰大模型
│   ├── llm_client.py           # 通用客户端（豆包 / Kimi / 商汤，换厂商只改 .env）
│   ├── prompts.py              # System Prompt（人设 + 纪律）
│   ├── tool_registry.py        # 工具的「说明书」+ 执行分发
│   ├── agent.py                # Agent 主循环
│   └── chat.py                 # 带工具的连续对话终端
├── tools/                      # 「真正的计算」层 —— 纯函数，不 print、不联网
│   ├── spectrum_loader.py      # 读两列光谱（自动识别编码 / 分隔符 / 表头）

│   ├── spectrum_quality.py     # 质量检查
│   ├── element_analysis.py     # 元素谱线匹配
│   ├── preprocess.py           # 预处理
```

## 已知坑（都是踩过的）

- **Windows 系统代理会静默掐断国内大模型接口。** 环境变量里明明没有代理，
  但注册表里的代理设置会被 Python 读到，`httpx` 默认 `trust_env=True` 会静默套上它，
  导致 TLS 被掐断、报 `SSL: UNEXPECTED_EOF_WHILE_READING`，而报错完全看不出是代理的锅。
  本项目已默认绕开系统代理直连。
- **低配账号限流很紧。** 带工具的一轮问答至少 3 次请求，某些账号 RPM 只有 3。
  客户端会按 `retry-after` 自动重试并打印提示，看到「限流」不是 bug。
- **思考型模型要把 `reasoning_content` 原样回传。** 手写
  `{"role":"assistant","content":...}` 会丢字段、破坏工具调用质量，必须用 SDK 提供的
  消息转字典方法。
